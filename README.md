# Networking-and-Cybersecurity

**Project 1: MQTT IoT End Devices (Mosquitto Broker) | Python (paho-mqtt)**

This project implements a Python-based MQTT IoT communication prototype using the paho-mqtt library, connecting to the Swinburne Mosquitto broker at rule28.i4t.swin.edu.au over TCP on port 1883 with authenticated username/password access. The system consists of multiple simulated end-device applications that demonstrate core MQTT publish/subscribe behaviour using both private, student-namespaced topics (<studentID>/private) and a shared public topic (public/topic2). One device periodically generates synthetic sensor telemetry—random temperature values between 20–30 °C and humidity values between 40–60 %—encodes the data in JSON format, and publishes identical payloads to both private and public topics at fixed 10-second intervals. Subscriber devices connect to the same broker, subscribe concurrently to the private and public topics, and continuously listen for incoming messages using a non-blocking MQTT loop, where each received payload is UTF-8 decoded, parsed from JSON into Python data structures, and printed to the terminal together with its source topic. An integrated device implementation further demonstrates bidirectional MQTT communication by simultaneously publishing telemetry and subscribing to both topics within a single client instance. The code follows the standard MQTT client lifecycle (Client, connect, subscribe, publish, loop_start) with keep-alive handling and graceful shutdown on interruption, and showcases practical IoT messaging concepts including topic hierarchy, namespace isolation, public topic visibility, real-time data exchange, and terminal-based monitoring of distributed IoT data streams.

**Proect-2: Secure MQTT-Based IoT Communication Using TLS and Certificate-Based Authentication**

This project hardens an MQTT-based IoT messaging solution by deploying and securing a Mosquitto broker on the RULE host and refactoring the Python clients to use TLS-encrypted MQTT with certificate-based trust. On the server side, the provided mosquitto.conf and aclfile are placed in /usr/local/etc/mosquitto, Mosquitto logging is enabled by creating the log directory (mkdir /var/log/mosquito) and debugging via /var/log/mosquitto/mosquitto.log, user authentication is enforced by creating /usr/local/etc/mosquitto/pwfile with username:password entries (no trailing blank lines) and hashing it using mosquitto_passwd -U /usr/local/etc/mosquitto/pwfile, and the service is configured to start on boot via mosquitto_enable="YES" in /etc/rc.conf and managed using /usr/local/etc/rc.d/mosquitto start|stop|restart (restart required after configuration changes). The broker is then reconfigured to support encrypted communications using certificates (TLS) and to listen on the secure MQTT port 8883. On the client side, the Python applications use the paho-mqtt library to connect to the broker at 136.186.230.88:8883 with username/password authentication, and load TLS material at runtime via required command-line arguments -ca_cert, -client_cert, and -client_key (validated using argparse with program termination via sys.exit(1) if any argument is missing), configuring TLS using client.tls_set(ca_certs=…, certfile=…, keyfile=…) and enforcing certificate verification with client.tls_insecure_set(False). The publisher/subscriber device continuously generates simulated telemetry (random temperature values between 20–30 °C and humidity values between 40–60 %, rounded to one decimal place), serializes the data as JSON, and publishes every 10 seconds to both the private topic 103796548/private and the public topic public/topic2, while also subscribing to these topics and printing decoded and parsed incoming messages via an on_message callback. A dedicated subscriber client subscribes to the same topic list, runs a non-blocking network loop using client.loop_start(), UTF-8 decodes each received payload, parses it using json.loads, prints the originating topic and data, and supports clean termination on KeyboardInterrupt with an explicit disconnect. The repository includes the certificate and key artifacts used for TLS, including root2.crt (CA certificate), mqttserver2.crt (client/server certificate), mqttserver2.key (private key), and supporting PKI files such as root2.key, req.csr, and v3.ext, with the accompanying report documenting that these were stored on the RULE host under /usr/local/etc/mosquitto/mosquittoProjectFiles2/ and referenced in the Mosquitto TLS configuration via cafile, certfile, and keyfile while listening on port 8883.
